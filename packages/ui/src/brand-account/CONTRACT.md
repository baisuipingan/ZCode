# 品牌账户 UI

2026-11-13客户端收口遵循docs/fork/25：输入区是模型与推理选择的唯一操作入口；正常就绪不在侧栏和账户页重复常驻。不可用原因只从Host安全错误码投影，不显示原始服务端正文。停用、分组无权、凭据过期/配额耗尽不提供误导性的“反复刷新”主动作；需要登录时由用户明确选择重新登录，临时故障才提供重试。目录同步失败保留上次列表时，仍展示具体失败原因和上次同步时点。错误来源不明的401不由UI推断或清账号。

设置中的“账户与用量/账户消费记录”描述服务端当前Agent连接的已结算记录；“本地使用统计”保留原统计范围，仅品牌模式明确区分命名。登录内容可嵌入设置，窗口拖拽/窗控与满屏外壳只属于独立登录入口。

允许本地浏览时，signedOut/expired仍显示登录/过期状态，不能留下空白的禁发提示。恢复动作打开现有账户设置中的嵌入登录；已登录但需重新授权时先退出失效会话再导航，不创建第二个授权入口。初始化显示加载状态。

遵循 `docs/fork/09-account-wallet-spec.md`、`10-account-wallet-impact-and-cases.md`、W3 的 `14-managed-agent-inference-spec.md` 与 `23-desktop-browser-login-spec.md`。23 取代登录页内密码/2FA主入口，历史记录不代表当前交互。

根 Provider 只从 base services 取可选 `brandAccountService`。Host 是当前账户、登录材料、余额和订单唯一 owner；组件订阅脱敏快照并发送命令。不会向官方 UserInfo store 写入品牌用户，不向远端 workspace 发送凭据。

UI 仅持有表单、打开的充值弹窗、当前查看订单及交互错误。进入账户/充值、恢复焦点和网络、点击刷新均请求服务；余额不自加减。切换账户/epoch 清除订单和登录草稿，旧请求不得覆盖新身份。

登录页通过 Host 的 `startBrowserLogin()` 和现有平台 `openExternal()` 打开系统浏览器；密码、验证码和2FA都由网站处理。UI 只订阅 `snapshot.browserLogin`，提供等待和取消，不持有 verifier、授权码或 token。打开浏览器失败即取消该操作；离开登录页前先完成取消。浏览器授权成功后仍使用原账户余额与托管推理，不增加第二份账户或模型连接。

登录安全错误提示独立于 loading/loadFailed/ready 内容分支。后续初始化失败不能把 Host 已返回的具体安全错误替换成笼统的账户服务加载失败；已有明确错误时只保留该原因与原有重试。交互错误仍仅属于当前账户 epoch，不显示原始异常正文。

关闭支付弹窗不取消订单；本人列表恢复待处理订单，只有 COMPLETED 宣告到账并刷新本人信息。二维码来自服务端，HTTPS 支付链接通过平台系统浏览器打开；其他支付形态明确说明本版不支持，提供网站订单入口但不承诺网页可恢复原支付流程，绝不把 client_secret/intent 当链接。网站订单入口仍需确认使用同一账号，付款后回客户端查询服务器状态。

品牌模式保留原官方组件源码，在 Root 装配层停止 OAuth、套餐、奖励、营销请求。W3 由 Host 提供安全的 Agent 连接状态，未配置时 Composer 与 SessionPane admission 禁止新发、续发、排队、重试及压缩等推理命令；configured 仍须经目标 CLI 确认配置后执行，不能落回官方模型。

消费历史仅渲染 Host 的 `snapshot.usage`，不保存第二份列表、余额差账本或额外轮询。刷新复用余额同步，既有初始化/焦点同步由根 Provider 处理。展示当前 Agent 连接的最近20条已结算消费，明确包含跨设备与辅助请求、未合并旧连接历史。失败保留同账户旧结果并标待同步，空结果不表示零消费。credits 金额直接展示 Host 给出的 USD 十进制字符串，以 `≈`/`<` 标记相应精度，不使用 Number 转换；旧计费金额沿用现有金额格式化，可靠金额缺失显示待确认。界面不暴露凭据和 credits 概念。

模型刷新遵循 `docs/fork/18-agent-model-refresh-design.md` 与 `19-agent-model-refresh-ui-acceptance.md`。根 Provider 发送焦点、联网、可见和前台五分钟检查意图；Host 唯一持有新鲜度、single-flight、成功时间与刷新错误。手动模型刷新 force=true，自动意图 force=false，余额刷新保持独立。模型目录复用已有 Registry 订阅；品牌 Composer 只挂载简化模型控件，候选与显式选择不由账户 UI 另存。刷新不得调用选型回调、覆盖草稿或为失效模型选择新默认值。显示名来自模型条目顶层 displayName，不进入执行配置或模型 ID。

账号布局遵循25号方案：侧栏正常状态只保留身份和余额两行，小刷新和充值为各自独立按钮；成功同步时间放提示，只有读取失败或会话问题扩展提示，不常驻模型就绪状态。账户页合并身份与钱包为一张概览，下方使用现有 Tabs 显示账户消费、充值记录；页签仅为本地展示状态，不重建订单owner、钱包或支付流程。消费继续使用快照，订单继续复用本人列表和现有充值弹窗。切换页签不触发充值、不估算余额、不自动重放请求。

设置内未登录状态复用嵌入式浏览器登录内容，不带全页高度和桌面窗控；独立登录保留原外壳。切换账户/epoch 后，晚到旧订单不得出现在新身份下。验收覆盖390px/桌面、中英文、Zai浅深主题、页签键盘操作、充值入口、余额刷新、陈旧余额、换号隔离及嵌入登录。
