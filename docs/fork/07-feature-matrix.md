# 首版功能保留、隐藏与关闭矩阵

依据 2026-11-10—2026-11-11 源码审计；不是本轮已执行的裁剪。产品目标固定为 Windows/macOS 上开发与办公并行，用户无需理解 Key、供应商、MCP、Skills 和 CLI。S=源码证据；D=仅声明；N=需改；U=尚需实测。具体实现证据见 [桌面](01-desktop-architecture.md)、[执行](02-agent-execution.md)、[办公扩展](04-office-and-extensions.md) 与 [官方服务清单](03-official-services.md)。

处置：保留=首版产品能力；隐藏=底层启用/受管，普通 UI 隐藏；关闭=首版服务/入口/后台触发均停用，源码保留；删除候选=满足依赖门槛后可物理删除；待定=信息不足，不做删除决定。隐藏与关闭不同，不能把一个导航开关当成服务禁用。

## 可以物理删除什么

具体目录、删除顺序和构建引用的进一步核对见 [08 源码裁剪清单](08-pruning-plan.md)。尤其不能按名字整删 `coding-plan-subscription`：它还承载Agent使用的工作流、上下文预算和请求验证策略，须先迁出仍需策略。

本轮没有批准执行任何删除，也没有足够引用/运行证据支持整包清空。可以进入**后续物理删除候选清单**的是：仅服务原厂商套餐/充值的展示与请求适配、营销奖励及高速/闲时专用业务、官方分享发布适配、已经被自有品牌替换的产品宣传素材/链接。它们与本产品无业务价值的部分可裁，收益主要是减少维护和误外呼，体积收益必须实测。

删除顺序：先品牌能力策略关闭并完成正常/异常闭环 → `architecture:context` 明确公共边界 → `dep:refs`/knip 核验引用（含动态注册、预置插件、构建资产、远端同步、E2E）→ 清理专用实现与导出 → 同步 spec/文档/技能 → 必要类型、Lint、架构、工程/CLI 回归与 E2E。不得恢复已退役 App 业务单测来凑覆盖，也不能删除其仍被 CLI/E2E 使用的 helper。`docs/testing/unit-test-quality.md:10`、`:33` 为现行测试边界。

暂不建议物理删除：Provider 多协议、MCP/Skill/插件基础、终端、浏览器、Git、会话/恢复、shared identity、server/RPC，以及只因首版关闭而暂时没入口的 SSH/WSL/调度。先隐藏/关闭就能取得大部分产品简化收益，深删会直接增加回归和上游合并成本。

## 首版普通用户应看到什么（N）

首页：开发 / 办公、最近任务、选择文件或文件夹。任务页：描述需求、进度、需要确认的操作、成果预览、继续修改、导出。账户区：登录状态、余额、充值、实际消费、帮助。设置保留语言/主题/通知/存储等生活化项目；模型、MCP、Skills、终端路径、供应商和高级网络配置不作为正常操作步骤。现有 coding/office 模式入口可复用（`packages/ui/src/settingsPageHelpers.tsx:416`），但它只是 UI 模式选择，不是零配置依赖管理或办公质量保证。
