# 官方服务依赖与替换清单

## 结论与边界

保留本地执行器，通过独立的账户/计费适配层把 sub2api 身份转换为通用 Provider 配置。不要让 sub2api 模拟 ZAI 的组织、项目、套餐、双 JWT、闲时票据协议。`ZCODE_BASE_URL` 只参与一部分地址解析，还有独立业务 origin、CDN、插件、更新和硬编码默认值。

源码证据：`packages/shared/src/zcodeEndpoint.ts:3` 分别定义 ZCode、BigModel、OAuth、业务 origin 与 relay；`packages/services/src/oauth/providers/index.ts:20` 只实例化 BigModel/ZAI adapter；`packages/shared/src/project-access-token-client.ts:45` 的身份限定 `family: bigmodel | zai`，`:272` 读客户组织，`:363` 构造组织/项目 Key URL。sub2api 的 JWT 与模型 Key 应独立建模，详见 [接入方案](05-sub2api-integration.md)。

## 账户现状与替换风险

1. OAuth 服务具有 `refreshToken()` 框架（`oauthService.ts:999`），但无 adapter 实现时直接要求重新登录（`:1007`）。恢复时 401/403 会退出（`:608`）。这不能直接承担 sub2api 自动刷新，后者还需要多窗口 single-flight、轮转 token 原子落盘和退出代次保护。
2. 服务端/Node 凭据采用 AES-GCM 文件存储，默认 secret 从平台、home、用户名派生（`packages/services/src/credential/providers/credentialCipherProvider.ts:24`、`:37`）；不是 OS 钥匙串。`oauth/repo/oauthCredentialRepo.ts:13` 还有 active provider 与 ZCode JWT 镜像 key。新账号不要复用这些厂商镜像；正式发行补 OS 保护适配器。
3. 现有退出有会话代次与串行 mutation（`oauthService.ts:1032`、`:1057`），该思想值得继承。新账户 owner 不要与旧 OAuth 两套状态同时决定“已登录”。不要把配置刷新失败当退出，也不要把模型 Key 401 一律当 JWT 过期。
4. 远程同步可能传播 API Key / token（`NOTICE.md:43`）；首版禁用远程入口仍应避免将新 refresh token 放进通用配置同步。只向本地执行器提供必要推理材料。

## 可逆关闭的实施要求

N：新增品牌构建配置/能力策略是建议，不是现成统一开关。现在的可选构建开关只覆盖若干遥测和普通更新。按能力同时控制 UI 路由、Service factory、后台 timer/轮询、默认 Provider/插件数据；不要仅加 CSS 隐藏。保留禁用服务的类型化空实现或明确 unavailable 状态，避免破坏本地服务依赖图。

先验证：未登录启动、登录、发起/恢复任务、打开设置、插件页、帮助页、退出，各录一份脱敏请求清单（进程、触发、目的 host/path、是否有认证、用途）。品牌首切片下所有模型请求含辅助模型必须去自有网关；静态插件、浏览器访问与运行依赖下载按单独清单判定。不能靠域名全文搜索证明没有运行时动态请求。

暂未验证：哪些懒服务在各启动/导航组合实际被实例化，第三方插件二级网络，实际发行构建注入值，线上官方服务行为；这些必须由受控打包与运行抓包补证，不能从源码推定“已经零外呼”。
